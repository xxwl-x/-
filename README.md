# 信息可视化案例仓库规则

## 入库流程（按用户定义持续修订）
1. 先依据数据组织逻辑，在编年型、层级型、编目型、字母表型、地理图形五大类中确定唯一主分类；不能仅凭外观或局部图形判断。
2. 再确定具体标签，区分主标签与辅助标签。
3. 将原图拆分为可复核的基础数据集：每行一个独立对象，每列一个原子属性，每个单元格仅一个值；数字与单位分列，原始值与估测值分列。
4. 分析图形特性、使用的统计图形、制作方法和可复现制作流程。
5. 提炼视觉编码（数据字段→视觉通道）与视觉叙事（阅读路径、焦点、对比和组织关系）。
6. 案例报告 Markdown、基础数据 CSV、数据字典 CSV、数据局限说明共同入库；条件允许时额外提供 XLSX。
7. 图片估测的坐标、尺寸、颜色和比例必须标注“估测”；无法识别的字段留空或标记未知，不得虚构。
8. 分类定义变更时，以用户明确给出的数据逻辑为准，并同步检查既有案例归属。

## 五大类定义（当前已确立四类）

### 01｜编年型信息图形（Chronological Infographics）
以时间为唯一主导维度，按事件发生先后进行单向排列。核心特征：单向、不可逆、单维、基本不再分类；一个时间对应一个事件。不能仅因画面出现时间轴就归为编年型。
基础关系：一个时间节点 → 一个事件。

### 02｜层级型信息图形（Hierarchical Infographics）
以层级顺序为主要组织逻辑，单向、不可逆、顺序排列；各层级可以包含多个关键数据；整体以线性为主，但结构可变性强。
基础关系：一个层级 → 多个关键数据。

### 03｜编目型信息图形（Cataloged Infographics）
编目型 = 编年型 + 层级型。必须同时体现时间顺序逻辑与层级组织逻辑；不能仅因包含多个专题模块、目录或清单就归入编目型。

### 04｜字母表型信息图形（Alphabet Infographics）
将多个数据组中的独立数据元素均匀地、一个个分布排列；多个数据组并列展示；不要求固定顺序或严格规律。重点是独立元素的分布与逐项识别，不要求按字母顺序排列。

### 05｜地理图形信息图形（Geographical Infographics）
分类定义待用户进一步明确。暂不自行补充或替代用户定义。

## 标签规则
标签描述具体图形表达或组织形式，不替代五大类主分类。一个案例可以有多个标签，但只能有一个主分类。

## 案例目录规范
每个案例单独建立文件夹，至少包含：`分析报告.md`、`基础数据.csv`、`数据字典.csv`、`数据局限.md`。
